# AW1S — Planos de arquitectura

## 0.1.0.3 — Inteligencia recopila y persiste los datos del usuario

Fuente: aporte en conversacion (no documento adjunto).

### La idea, tal cual se planteo

Ademas de decidir que informacion hace falta (su rol ya definido en
0.1.0.1-SK), Inteligencia tambien recopila todos los datos del usuario y
los guarda en la base de datos.

### Como encaja con lo ya definido (interpretacion propia, a confirmar)

La spec original (0.1.0.1-SK) ya listaba que datos ve Inteligencia por
interaccion: mensaje, contexto disponible, historial relevante, metadata,
hora/fecha, IP, ID de usuario, ID de sesion, "otros datos tecnicos". Hasta
ahora Inteligencia solo los **leia** para clasificar. Este punto agrega que
ademas los **escribe**.

Esto separa la persistencia en dos momentos distintos, no uno solo como
sugeria el flujo original:

- **Inteligencia** persiste los datos crudos de la interaccion apenas
  llegan — las entidades estructuradas: Usuario, Sesion, Interaccion,
  Evento (ver modelo de datos en `documentacion/arquitectura.md#3`). Esto
  pasa temprano en el ciclo, no al final.
- **Memoria** sigue decidiendo, al cierre del ciclo, que de todo eso se
  eleva a Memoria semantica y se vectoriza (ver seccion 2.5). Esa parte no
  cambia.

O sea: Inteligencia deja de ser un componente de solo lectura. Pasa a tener
un efecto secundario (escribir en Postgres) ademas de su salida principal
(la necesidad de informacion).

### Punto a marcar con cuidado: alcance de "todos los datos del usuario"

Esto es una decision de producto, no solo tecnica, y vale la pena
resolverla explicitamente antes de implementar algo que despues sea caro
de deshacer (borrar datos ya recolectados de gente real, o explicarle a un
usuario por que se guardo algo que no esperaba):

- ¿"Todos los datos" son los ya listados en la spec (IP, hora, IDs,
  metadata tecnica), o incluye algo mas amplio (ej. huella del
  dispositivo, ubicacion aproximada por IP, patrones de uso)?
- La spec original ya condicionaba la IP a "cuando corresponda y sea
  legitimo obtenerla" — ese mismo criterio, ¿aplica a todo lo demas que se
  recolecte ahora?
- ¿Hay una politica de retencion (por cuanto tiempo se guarda, si se puede
  borrar a pedido) o eso queda para mas adelante?
- Si AW1S en algun momento sirve a mas de un usuario final (no solo el
  admin), esto empieza a tocar temas de privacidad/consentimiento reales,
  no solo diseno de base de datos.

No se resuelve nada de esto aca. Quedo marcado porque es de las pocas
decisiones de esta carpeta que no es "cara de revertir" solo en terminos
de arquitectura, sino tambien en terminos de datos de personas reales ya
guardados.
